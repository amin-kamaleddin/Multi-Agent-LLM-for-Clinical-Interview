# Single-LLM Baseline

This directory contains the **single-LLM baseline** evaluation for the structured clinical interview agent. The baseline tests whether a single LLM call — given only the raw interview transcript and the module's diagnostic criteria — can match the performance of the full multi-agent pipeline.

---

## Motivation

The multi-agent system uses a sequential pipeline of specialised nodes (Questioner → Patient → Evaluator → Navigator → Diagnoser) to conduct a structured interview and arrive at a diagnosis. This baseline answers a key question:

> **Is the multi-agent architecture actually necessary, or can a single powerful LLM reading the completed transcript produce equivalent diagnostic accuracy?**

This is a post-hoc evaluation: the transcripts are already generated by the patient agent. The baseline LLM never interacts with the patient — it reads the finished conversation and applies the same diagnostic criteria that the multi-agent Diagnoser node uses.

## Directory Structure

```
baselines/
├── README.md                                    ← this file
├── predictions_single_llm_combined.csv          ← all modules combined (matches prediction_combined.csv schema)
├── module_A/
│   ├── predictions_single_llm_gpt-4o-mini.csv   ← per-patient predictions (id, label, prediction)
│   └── diagnosis_{id}.json                       ← full LLM JSON output per patient (for auditing)
├── module_B/
│   ├── predictions_single_llm_gpt-4o-mini.csv
│   └── diagnosis_{id}.json
├── module_C/ ... module_D/ ... module_G/ ... module_H/
├── module_I/ ... module_J/ ... module_L/ ... module_P/
└── run_single_llm_baseline_{LETTER}.log         ← historical run logs (per-module, per-version)
```

Each `module_{LETTER}/` folder is created automatically when you run the baseline for that module. The combined CSV at the top level is updated automatically by `eval_single_llm_baseline.py`.

## Scripts

### `tests/run_single_llm_baseline.py` — Generate Predictions

Reads the completed interview transcripts for a module and calls the LLM once per patient to produce a diagnosis.

**Usage:**
```bash
# Run from repo root
python tests/run_single_llm_baseline.py --module A

# Force re-run even if predictions CSV already exists
python tests/run_single_llm_baseline.py --module A --force

# Run all supported modules sequentially
foreach ($m in @("A","B","C","D","G","H","I","J","L","P")) {
    python tests/run_single_llm_baseline.py --module $m --force
}
```

**Arguments:**

| Argument | Default | Description |
|----------|---------|-------------|
| `--module` | `A` | Module letter to evaluate (A–P, excluding O) |
| `--force` | off | Re-run even if `predictions_single_llm_gpt-4o-mini.csv` already exists |

**Input files required:**

| File | Description |
|------|-------------|
| `modules/module_{letter}.json` | Module definition: name, questions, diagnostic criteria |
| `backend/agent_core/interview_agent/prompts/patients_with_system_prompts_module_{LETTER}.json` | Patient metadata including ground-truth labels |
| `patient_agent_results/patients_with_system_prompts_module_{LETTER}/{id}.csv` | Completed interview transcript for each patient |

**Outputs:**

| File | Description |
|------|-------------|
| `baselines/module_{LETTER}/predictions_single_llm_gpt-4o-mini.csv` | `id, label, prediction` — one row per patient |
| `baselines/module_{LETTER}/diagnosis_{id}.json` | Full LLM JSON response per patient: all diagnostic groups with `reasoning`, `diagnosis`, and any optional fields (`timeFrame`, `insight`, `ticRelated`, `fearRestricted`) |

The per-patient `diagnosis_{id}.json` files exist for auditing and manual review. They are not consumed by any downstream script but can be inspected to understand the LLM's reasoning for a specific patient. Example structure:

```json
{
    "positive": {
        "diagnosis": true,
        "reasoning": "Criterion A1 (depressed mood): MET ...",
        "timeFrame": "recent"
    },
    "recurrent": {
        "diagnosis": false,
        "reasoning": "No prior episode described ..."
    }
}
```

**Model configuration:**

| Parameter | Value |
|-----------|-------|
| Model | `gpt-4o-mini` |
| Temperature | `0.1` |
| Max retries | `3` |
| Retry delay | `5 seconds` |

### `tests/eval_single_llm_baseline.py` — Compare Against Multi-Agent System

Loads both the baseline predictions and the multi-agent system's predictions for the same patients and prints a detailed side-by-side evaluation report.

**Usage:**
```bash
python tests/eval_single_llm_baseline.py --module A

# Run all modules
foreach ($m in @("A","B","C","D","G","H","I","J","L","P")) {
    python tests/eval_single_llm_baseline.py --module $m
}
```

**Arguments:**

| Argument | Default | Description |
|----------|---------|-------------|
| `--module` | `A` | Module letter to evaluate |
| `--reset-combined` | off | Delete `predictions_single_llm_combined.csv` before appending. Use on the first module of a full batch run to avoid duplicates |

**Input files required:**

| File | Description |
|------|-------------|
| `baselines/module_{LETTER}/predictions_single_llm_gpt-4o-mini.csv` | Baseline predictions (from run script above) |
| `patient_agent_results/patients_with_system_prompts_module_{LETTER}/predictions_gpt-4o-mini.csv` | Multi-agent system predictions |
| `backend/agent_core/interview_agent/prompts/patients_with_system_prompts_module_{LETTER}.json` | Patient metadata for stratification |
| `modules/module_{letter}.json` | Module definition (used to populate the `Module` column in the combined CSV) |

**Outputs:**

| File | Description |
|------|-------------|
| `baselines/predictions_single_llm_combined.csv` | Combined predictions across all evaluated modules — appended on each run. Schema matches `patient_agent_results/prediction_combined.csv` |

The combined CSV has the following columns:

| Column | Example | Description |
|--------|---------|-------------|
| `id` | `1` | Patient ID |
| `label` | `TRUE` | Ground-truth diagnosis (TRUE / FALSE) |
| `prediction` | `TRUE` | Single-LLM baseline prediction (TRUE / FALSE) |
| `Module` | `A - Major Depressive Episode` | Module letter and full condition name |
| `Tier of Symptom Disclosure` | `Tier 1: Superficial/Vague` | Patient presentation tier (T1–T5) |
| `Expected Symptom Direction` | `Positive Symptom Presentation` | Whether the patient is a positive or negative case |
| `Emotion/Tone Tier` | `Flat/Detached` | Emotion/tone category of patient persona |

**Recommended batch run command (regenerates combined CSV from scratch):**
```bash
# From repo root — reset combined on first module, then append for the rest
$first = $true
foreach ($m in @("A","B","C","D","G","H","I","J","L","P")) {
    if ($first) {
        python tests/eval_single_llm_baseline.py --module $m --reset-combined
        $first = $false
    } else {
        python tests/eval_single_llm_baseline.py --module $m
    }
}
```

**Report sections:**

1. **Overall metrics table** — Accuracy, Precision, Recall, Specificity, F1, F2, and confusion matrix (TP/TN/FP/FN) for both systems side-by-side with delta.
2. **McNemar's test** — Statistical significance of the difference between the two classifiers on the same set of patients (with Yates continuity correction).
3. **Stratified F2 breakdown** — F2 (or Recall/Specificity for single-class strata) broken down by:
   - *Tier of Symptom Disclosure* (T1 Superficial/Vague → T5 Rich/Nuanced)
   - *Expected Symptom Direction* (Positive vs. Negative Symptom Presentation)
   - *Emotion/Tone Tier* (Emotional/Expressive, Flat/Detached, Neutral/Cooperative)
4. **Disagreement list** — Patient IDs where the two systems produced different predictions, including their true label and symptom tier.
5. **Summary verdict** — Which system wins on F2, by how much, and whether it is statistically significant.

**Why F2?** F2 weights recall twice as heavily as precision (β=2). In a clinical screening context, false negatives (missing a true case) are more costly than false positives, so F2 better reflects the clinical cost structure than F1.

## How the Baseline Works

### Transcript formatting

Each patient's interview is stored as a CSV with columns `question_id`, `ai_question`, `patient_response`. The script reads these and formats them into a plain Q&A text block:

```
Q: Have you been feeling sad or depressed most of the day?
A: Yeah, pretty much every day for the past few weeks.

Q: Have you lost interest in things you used to enjoy?
A: Definitely. I don't even want to watch TV anymore.
```

### System prompt

The LLM receives a system prompt containing:
- Its role as a SCID-style psychiatric diagnostic evaluator
- The full diagnostic criteria for the module (extracted from `modules/module_{letter}.json`)
- The required output schema (JSON with `reasoning` and `diagnosis` fields per diagnostic group)
- Module-specific optional fields:
  - Module A: `timeFrame` (`"past"` | `"recent"` | `"both"` | `null`)
  - Module G: `insight` and `ticRelated`
  - Module F: `fearRestricted`

### Output schema

The LLM returns a JSON object matching the multi-agent Diagnoser node's output schema exactly, enabling direct comparison:

```json
{
  "positive": {
    "reasoning": "Patient endorsed depressed mood daily for 3 weeks...",
    "diagnosis": true,
    "timeFrame": "recent"
  },
  "recurrent": {
    "reasoning": "No prior episode mentioned...",
    "diagnosis": false
  }
}
```

Groups vary by module:
- `positive` + `recurrent`: most modules (A, B, C, G, H, I, J, L, O)
- `lifetime` only: modules P, D
- `current` only: some modules (no `recurrent` field)

### Diagnosis key

The primary prediction for each module is extracted from a specific group key:

| Group key | Modules |
|-----------|---------|
| `positive` | A, O, B, C, H, I, J, L, G |
| `lifetime` | P, D |

If the primary key is missing in the response, the script falls back to `current`, then `positive`, then `lifetime`.

### Output normalisation

The raw LLM response is normalised to match the canonical multi-agent field ordering (diagnosis → reasoning → optional fields), with null optional fields omitted. This allows direct JSON diffing with multi-agent output files.
